# ADR 0002: Python 3.14 та фундамент персистентності

## Статус
Прийнято — 2026-10-01

План виконання: [persistence-foundation](../plans/persistence-foundation.md)

## Контекст
Перед реалізацією CRUD бракувало інфраструктурної основи: міграцій, налаштувань, сесії та тестового середовища з БД.

## Рішення
- **Python 3.14** у Docker (`python:3.14-slim`) та локальному `.venv`; `requires-python` лишається `>=3.12`.
- **Конфігурація через `pydantic-settings`** (змінна `DATABASE_URL`), а не напряму з `os.environ`.
- **Тести з реальним PostgreSQL**, а не SQLite/моки: окрема БД `<POSTGRES_DB>_test` у тому ж compose-сервісі `db`; кожен тест — у транзакції з rollback (savepoint).
- **Схема тестової БД створюється через `Base.metadata.create_all`**, не через Alembic.

## Наслідки
- Тести `domain`/`application` і далі можуть використовувати фейкові репозиторії; інтеграційні тести репозиторіїв ходять у реальний Postgres.
- Міграції не перевіряються тестами (схема через `create_all`) — розбіжність моделей і міграцій потрібно ловити окремо.
- Для `make test` потрібен запущений Docker і файл `.env` (копія `.env.example`).
