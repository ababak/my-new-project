# ADR 0003: Семантика CRUD API задач і межа транзакції

## Статус
Прийнято — 2026-10-01

План виконання: [task-crud-api](../plans/task-crud-api.md)

## Контекст
Фундамент персистентності (ADR 0002) готовий; потрібен публічний API для керування задачами в межах Clean Architecture (ADR 0001).

## Рішення
- **Часткове оновлення через `PATCH`**: відсутнє поле означає «не змінювати» (sentinel `UNSET`), `description: null` очищає опис, `title: null` відхиляється (422).
- **Будь-який статус можна встановити з будь-якого**: обмежень на переходи між статусами немає. Окремого ендпоінта «complete» теж немає — завершення задачі це `PATCH /{id}/status` зі `status: "done"`.
- **Репозиторій** (`infrastructure/db/task_repository.py`) робить `commit` у кожному методі запису; транзакція одна на операцію.

## Наслідки
- Транзакційна межа в репозиторії означає, що операція, яка змінює кілька агрегатів, потребуватиме винесення `commit` (наприклад, у unit of work); тоді потрібен новий ADR, що замінить цей.
- Завершену задачу можна повернути в `todo`; сервер цього не забороняє.
